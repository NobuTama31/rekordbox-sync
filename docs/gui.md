# Desktop monitor

CustomTkinter 6.0によるダークテーマのWindows向けGUIです。追加依存は`.[gui]`で導入します。

## 構成

- `gui/app.py`: メインウィンドウ（単一画面＋JSON切替）、設定、UIスレッドでの更新。
- `gui/widgets.py`: デッキとミキサーの表示部品・デザイントークン。画面は1枚のコンソール（デッキ｜ミキサー｜デッキを罫線で区切る）に、運用情報は下部のステータスバー（ラベル付きセグメント＋状態ドット）へ分離。オレンジはアクセント（デッキ見出し・テンポ差%・フェーダーの信号充填）。状態ドットは正常=緑、警告=琥珀、エラー=赤。フェーダーはCanvas自描画のツマミ付きスライダー（CTkProgressBarの描画癖を避けるため）。
- `gui/presentation.py`: 数値・テンポ差・CSV照合結果の表示整形。
- `gui/client.py`: HTTP取得と最新1件のメモリ上の受信キュー。
- `gui/controller.py`: GUIが必要な場合だけ所有するローカルAPIの開始・停止。

画面は既存/state/enrichedを参照します。CSV未設定や未対応のAPIは/stateへフォールバックし、CSVが未取得であることを表示します。
ネットワークI/OとAPI起動・停止はバックグラウンドで実行し、Tkの操作はメインスレッドに限定します。
GUIのimportでデバイス・API・ウィンドウは起動しません。GUI依存を含まないテスト環境でも表示整形とHTTPクライアントは検証できます。

## 操作

- セッション: 2台のデッキ、現在BPM＋テンポ差%＋元BPM（1行）、CSV情報（デッキ下部に固定、TVA | 放送年：の1行形式）、フェーダー（ウィンドウの高さに応じてストロークが伸縮）、ステータスバー（Rekordbox/FLX4/CSVの状態、API稼働状態とアドレス、取得元、UI更新時刻、通知）。ヘッダーにパッケージバージョンを表示。
- JSONインスペクター: 現在のレスポンス表示とクリップボードコピー。ファイル保存は行わない。
- APIを起動: ローカルAPIがなければ公開サービスを利用して起動。既存APIは再利用。
- APIを停止: このGUIが起動したAPIだけ停止可能。
- 接続設定: API URL、CSVファイル、MIDIポート名。CSV選択ダイアログあり。診断オプション（おかしい取得を logs に保存）もここで切り替える。通常監視はスナップショットを保存しないが、このオプションを有効にした時だけ、パース失敗またはロード済みデッキのBPM欠けが起きた取得の raw を logs/latest_uia.json に上書き保存し、さらに logs/history/ に時刻付きで全件残す（1秒に1件まで）。logs/history/index.jsonl に1件1行（時刻・capture_mode・要素数・ウィンドウ名）で索引が付くので、起動から終了までの劣化の経過を追える。serve では --save-suspect-captures / --keep-suspect-history で有効化できる。
- APIを開く: ブラウザで/stateを開く。

起動例:

```powershell
python -m rekordbox_sync gui --catalog assets/song_info.csv --start-api
```

既存のAPIを表示するだけなら--start-apiは省略できます。GUI自身がAPIを起動した場合はウィンドウ終了時にHTTPと監視ソースを解放します。
既存APIに接続した場合、CSV/MIDI設定はそのAPIへ送信しません。既存APIの設定変更はその起動元で行ってください。
接続設定は起動中のメモリだけに保持します。再起動時はコマンドライン指定を使います。

## 表示の意味

- LOADEDは曲がロード済みという意味で、再生中やON AIRを示さない。
- 時間バーは最後に取得した経過/残り表示から計算する。取得間隔の補間や疑似アニメーションをしない。
- 不明値はダッシュまたは未受信。0%とは区別する。
- HTTP接続切れ時や受信更新停止時は古い表示をクリアする。
- ファイルは蓄積しない。ログイン・テレメトリー・自動アップデートはない。

Windowsの一部の仮想環境でTcl/Tk探索に失敗する場合、実行中Pythonに同梱されたtclディレクトリをプロセス内だけで参照します。システム環境変数は変更しません。
